# CET-4 Studio｜交给 DSH 的开发任务书 v1.0

版本：2026-11-03 / 产品负责人：用户 / 研发执行：DSH / 本文定位：可实施的产品需求、交互说明、技术方案与验收合同。

> 本文件是研发任务要求，不是已完成的产品。DSH 不应将界面占位、模拟计数、伪造题库或空按钮当成完成。优先完成从真实资料导入到训练、标注、复盘和导出的闭环。可以调整具体工程框架，但不能擅自删除核心流程与验收标准。

## 0. 产品定义和目标

**产品名称**：CET-4 Studio（四级听力与精读工作台）

**使用场景**：一名 Windows 电脑用户，备考 2026-12-12 的英语四级。用户现有约 15 套真题，文件可能包含文字 PDF、扫描 PDF、DOCX、TXT、JPG/PNG、整套 MP3 音频、纸质听力原文照片等。安装后本地浏览器使用，资料与学习记录全部保存在电脑中；可离线运行。

**核心目标**：提高四级听力做题能力，同时借助真题精读积累不认识的词、短语、句式；所有标注自动汇总到个人表达库，支持重复练习、筛选与导出。

**用户真实障碍**：
- 看得懂一些熟词，但连续语流中辨认不出来（音形映射薄弱）；
- `terrified of`、`to the point where` 这样的表达可能根本不理解；
- 听见零散词，却无法组织为人物、事情、原因与结果；
- 听懂局部内容仍可能因为题目问法、同义替换或关键事实而答错。

**产品学习立场**：真题做题为主，背诵/表达学习作为补充。不以看过多少材料、反复播放多少次冒充进步。允许用户导入自制短文及自行用其他工具生成的配音；**本项目不负责自动合成或替用户制作 MP3**。

### 必须支持的四条完整闭环

A. **真题听力**：导入试卷与真实录音 → 按八段听力篇章定位 → 无稿首听并答题 → 核对题目/答案 → 标记错误原因 → 对照原文精听 → 无稿重听 → 完成训练并记录。

B. **自由精读**：导入或粘贴文本 → 鼠标选中任意单词/短语/句式 → 设标签/释义/备注 → 持久化 → 回到原文可见标注。

C. **表达库复习**：跨篇聚合同一表达 → 可查看多个出现位置和句子 → 标记不会/模糊/已掌握 → 筛选和导出 TXT/CSV/XLSX（优先 CSV；后续 XLSX）。

D. **资料管理**：批量导入混合文件 → 统一按考试年月/套数/题型/篇章组织 → 原件可追溯 → OCR 校对与合并去重 → 备份、恢复。

## 1. 用户故事与非功能约束

### 1.1 关键用户故事

- 当我打开一套真题的听力，我希望先只看题目和选项，不看到原文；可以一口气听完对应篇章后答题。
- 当我答错，我希望能判断：没听出认识的词、词本来不认识、短语/句式不熟、跟不上语速、找不到关键信息、题意理解错或同义替换没认出，而不是只显示一个红叉。
- 当我需要精听，我希望把 20–40 秒、某一句或任意 A-B 区间反复听，切换 0.75/0.9/1/1.15/1.25 倍速、快速跳转和显示/隐藏原文；不必每次从 24 分钟整段重新听。
- 当原文已知而没有句级音频时间戳时，我能手工给一篇、一句标记大致时间区间，尽快开始使用。
- 当我遇到不认识的短语，我选中它后可以添加标注，并且多次出现不会在词库里制造重复主条目。
- 当我次日复听，能只看昨日的薄弱篇章、错误题和不熟悉的表达；再次听不出应继续标记，不能因“听过”而自动认定掌握。
- 当我的试卷 MP3 中的问题与电子 PDF 问题存在冲突，系统应同时保留两个版本，并突出提示来源差异；用户可以选定听力考试实际录音题干为训练依据。

### 1.2 首期不做 / 禁止伪装完成

- 不实现云端账号/会员/社交/排行榜/复杂推荐算法/打卡动画；不需要互联网服务。
- 不要求自动语音识别、自动句子精准对齐或自动翻译高准确率。这些可以作为**可选增强模块**，手工关联与校对必须可用。
- 不把题干、答案、中文释义或句级时间戳编造出来。缺失信息应明确显示“未录入/待核对”。
- 不以音频播放时长直接等同理解能力；统计由可追踪的真实操作组成。
- 全站每个可见按钮必须有真实动作、状态反馈、错误处理；未做的功能不要显示成可点主按钮。

## 2. 信息架构（路由与导航）

左侧全局导航（桌面 236px）：
1. `/dashboard` 今日学习：继续上次训练、未完成篇章、需复习表达、最近材料。
2. `/library` 真题资料库：年份/月/套/题型/篇章树形目录，搜索、导入、管理。
3. `/listening/:sessionId` 听力工作台：核心页面（考试、精听、无稿验证）。
4. `/reading/:passageId` 精读页面：原文阅读与单词短语句式标注。
5. `/vocab` 我的表达库：去重条目、多个例句和出处、复习、导出。
6. `/mistakes` 错题/薄弱点：按原因/年份/题型筛选、回跳对应音频位置。
7. `/imports` 导入管理：多文件导入、匹配关系、识别预览、OCR 校对、失败重试。
8. `/settings` 设置/备份：本地目录、字体/显示、快捷键、备份恢复、诊断日志。

一级导航仅 7–8 项，不加无意义菜单。网页以中文为主要 UI 文案，英语内容高可读性。

- **页面底色**：`#F7F9FC`；内容卡片 `#FFFFFF`；标题深蓝灰 `#162338`；主文本 `#263246`；辅助灰 `#718096`。
- **品牌强调色**：`#4F6BFF`（蓝紫），深色 hover `#3F56D8`。成功/已掌握 `#24A47A`，提醒 `#E9A23B`，错误 `#E05D61`。
- **标注色**：生词柔黄 `#FFE49B`；短语柔蓝 `#BFDFFF`；句式柔绿 `#C4EDCE`；播放定位淡紫 `#E6E5FF`。不仅依赖颜色，还配小图标/悬浮提示。

- **动画**：150–220ms 微反馈；不做持续闪烁、过量渐变、动态背景；支持减少动态效果。

### 3.3 页面细节

**Dashboard**：最上方「继续上次训练」大按钮；第二排三个量化指标：真题已训练篇章/总数、待复听薄弱篇章、待复习表达数量；下方最近试卷。数据为空时提供导入入口，不显示虚拟进度。

**资料库**：顶部搜索；左侧年/月/卷树；中央材料卡片（每套显示有无 PDF/原文/录音/答案、整理状态）；右侧导入/关联文件操作。卡片必须能打开实际篇章，不允许仅弹假通知。

**听力页**：模式分段控制「①首听做题 ②错因诊断 ③精听 ④无稿复听」。每个模式对应明确数据存储与按钮状态。主区域可以题目/英文原文两种布局；右侧错误原因、词句卡片、笔记。底部播放器包含波形、时间轴、播放/暂停、向前/后跳 5s、速度、A/B 点、循环开关、选择篇章、音量、快捷键提示。

**阅读页**：文章阅读主栏 + 右侧标注卡。可隐藏中文、开启行距调整。鼠标划词弹出小浮条：`单词` `短语` `句式` `忽略`；卡片可修改类型、释义、笔记、熟练度。

**表达库**：左侧过滤器（全部、听力、阅读、词/短语/句式、不会/模糊/已掌握、年份套数）；中心表格/卡片；右侧选中详情，含原句、出处、跳回原文、多个出现位置；上方导出按钮可预览。

**导入向导**：第1步选择文件；第2步自动提议年份、月份、套数、文件角色；第3步可编辑提取结果/拆篇/匹配音频；第4步检查与提交入库。文件失败时保留原件并可重新解析。

## 4. 核心功能规格

### 4.1 文件导入及模型

支持：文字 PDF、扫描 PDF、DOCX、TXT/MD、JPG/PNG/WebP、MP3/WAV/M4A（浏览器能解码的音频为准，失败给出转码提示）。旧 DOC 可提示转换后导入，优先级次之。

统一流程：保存原件(不可变) → 类型/MIME 验证 → SHA-256 判重 → 抽取文字/OCR → 保留页码与来源区域 → 可编辑的规范化段落 → 用户确认归属 → 建立题型和篇章 → 如有关联音频则设置起止时间 → 提交成功。

**考试分类**：`考试年份` + `考试月份` + `套数` + `题型` + `Section` + `篇章/题目`。允许同一卷绑定多个原件，例如试卷 PDF、五张听力原文照片、MP3、答案解析，互不覆盖；可以单独导入无年份的练习文章。

**原文源别**：有 `source_type` = printed_transcript / audio_transcription / question_pdf / question_audio / user_entered / answer_key / generated_practice。存 `verified_status` = unverified / user_verified / conflict。尤其**音频录音实际问句和 PDF 重写题目不能当成同一字段覆盖**。

**OCR**：自动检测每页是否可提取文字；扫描页才进入 OCR；文本提取结果需允许手动修正。双栏、题号、选项、图片说明需要人工预览确认。OCR 置信度不佳可显示“待校对”，不以机器产出冒充准确原文。

**拆篇**：支持光标选中段落→创建/移动到某篇；手工修改标题/归属/题号；重复上传时弹出替换、关联已有试卷、独立保存三个选择。原始文件不删除。

### 4.2 听力：首听做题（优先最高）

- 进入某套后选择「全套练习」或「单篇练习」。四级听力八个篇章：3 篇新闻、2 段长对话、3 篇听力篇章（各篇关联对应题号），界面不硬编码题数，使用试卷的实际数据。
- 默认**不显示英文原文、中文译文、正确答案和题目解析**。播放本地真实音频；选择模式时记录 sessionId、paperId、questionSetVersion。
- 练习页显示录入的 A/B/C/D 选项及题号；“未录入题目”状态应可播放音频但标为无法答题，不得自动制造题目。
- 支持单次播放考试模拟模式（学生主动选择），限制界面重放和进度拖拽；关闭模拟则是普通练习（可回放）。**单次模式只约束本次交互，不声称能防止绕过**。
- 答题完点击「提交本篇」→显示答对/答错/未录入答案，不泄漏答案在提交前；持久保存首次提交结果，后续重做产生新 session，不覆盖原成绩。
- 核对时如果录音问句与 PDF 文字不一致，突出显示 `录音题干`/`PDF题干` 标签。用户可选择按录音题目训练，答案依据可编辑并标明“待核对”。

### 4.3 听力：错因诊断

答题提交后每道错题可选择一个或多个原因：
1) 词认识但没听出来（声音识别）；2) 生词/短语没学过；3) 连读/弱读/语速难；4) 听见词但整句没理解；5) 关键信息漏听；6) 问句/选项理解错；7) 同义替换没认出；8) 其他/不确定。

可以给某一道题绑定原文证据句、音频时间位置、自己的笔记；支持“虽答对但猜的”状态。系统不根据分数自动猜测错因。

### 4.4 听力：精听工作台（核心竞争力）

- 播放整段音频，按 `audio_segment` 的起止秒定位至一篇（无标记时用户可手工拖 A/B 点定位）。
- 播放器：空格播放/暂停（文本输入聚焦时不拦截），←/→±5 秒，`[` A 点，`]` B 点，`L` 循环，0.75/0.9/1/1.15/1.25 倍速，时间进度，音量，可鼠标拖动波形或时间轴。
- 任意 A/B 区间循环：A < B、二者在素材时长内；播放到 B 回到 A，允许关闭循环；切换篇章自动清理或为该篇独立保留 A/B 标记。
- 原文显示四档：完全隐藏 / 仅当前句 / 整段英文 / 英文+中文（中文仅在用户录入时显示）；不能每进入页面都默认曝光原文。
- 句级或段级音频时间对齐：手工标记起止时间为首期可靠功能；自动 ASR 对齐如果实现，标记 `机器建议` 并可校对，不能以自动对齐取代真实原文。
- 点击原文句子→播放关联音频区间；点击声音标记→滚动到对应句子。无句级时间戳时不可假装自动同步。
- **听写与复述**：隐藏原文，输入自己听到的英文；显示原文后提供差异比较（词级文本差异，忽略大小写/标点的可选设置）并保存版本；“中文复述”可输入事件概要，无 AI 判分时只保存并支持自评（能说清人物/事情/原因/结果）。
- 对单句可添加“听不出，但看得懂”/“看了也不懂”/“只听到部分”标记；后两者提供直接加入表达库的入口。
- 无稿复听：默认隐藏原文与笔记，再听一遍并手动回答内容理解问题或自评；记录与首听分开保存。
- **考试题与精听互通**：错题卡可一键跳到对应音频区间及文字证据；原文位置可跳回题目。

### 4.5 词/短语/句式标注

- 用户鼠标双击单词或拖选连续英文片段后弹出工具条；可以选择单词、短语、句式；颜色与图标有一致映射。
- 允许**嵌套、部分重叠标注**，例如 `point` 与 `to the point where`，不能因为 `<mark>` DOM 嵌套冲突丢掉标注。优先使用 anchor 数据层 + 渲染段切分或 CSS Highlights API 的渐进增强，而不是直接修改原文数据库。
- 每条 occurrence 存：passage_id、text_revision_id、start_offset/end_offset（Unicode code point 规则明确）、quote_exact、prefix/suffix、context_sentence、category、master_entry_id、created_at；原文修订后按引用+上下文重定位，不确定时标记为待修复，不静默错位。
- 表达库 master_entry 通过 normalize（大小写/空格/弯引号统一）判重，**不对长短语做过度词干化/错误合并**；保留每处独立标注和来源。
- 标注编辑卡可输入中文释义、备注、熟练度（不会、模糊、掌握），允许仅留空待补；不强求上线在线词典。可以批量导出没有释义的表达，后续补。
- 加标注后无刷新即出现颜色；自动保存提示；刷新/重启保留；Undo/Redo 至少覆盖最近新增/删除操作。

### 4.6 复习与导出

- 表达库按首次添加、出现频次、掌握状态、题型、来源试卷、标注类别排序与筛选。
- 表达卡展示主条目+释义、一次例句与可展开的多个出处，点击跳回对应篇章及时间点（如有）。
- 导出字段可选：英文、类型、中文、原文例句、来源年月卷、题型、标注次数、掌握状态、个人备注。
- 首期支持 UTF-8 with BOM CSV、TXT、JSON 完整数据备份；XLSX、Anki TSV/CSV 在后续任务中完成，编码要在 Excel 中文 Windows 测试。
- 导出作用域可选择：所有、选中年份/套、仅听力、仅阅读、不会/模糊、只某类型。能预览将导出多少条，去重主条目但可以选择展开所有出现记录。
- 每日复听队列：根据用户标记/日期创建 `复听待办`，优先未听懂篇章、昨日错题对应音频、最近生词例句；默认不自动把听过等同掌握。提醒不是强制任务。

## 5. 数据模型（SQLite 初稿）

所有表主键 UUID/ULID 或自增均可；时间用 ISO 8601 UTC；数据库 migration 必备。以下为实体，DSH 可规范化字段，但不可省掉关键关系。

| 表 | 核心字段 | 说明 |
|---|---|---|
| `papers` | id, year, month, set_no, title, status | 一套试卷 |
| `assets` | id, sha256, relative_path, mime, size, original_name, asset_kind | 原始 PDF/照片/音频/文档，不可覆盖 |
| `paper_assets` | paper_id, asset_id, role, source_type | 一套试卷多文件 |
| `passages` | id, paper_id(nullable), type, section, ordinal, title, text_current_revision | 一段新闻、对话、阅读或练习短文 |
| `passage_revisions` | id, passage_id, content, editor, created_at, source_asset_id | 规范化文本和历史修订 |
| `audio_tracks` | id, paper_id, asset_id, duration_ms, source_status | 音频资源信息 |
| `audio_segments` | id, track_id, passage_id, start_ms, end_ms, label, confidence, verified_status | 篇章/句子的时间范围 |
| `sentences` | id, passage_revision_id, start_offset, end_offset, order_no | 句级原文区域，时间可经 segment 关联 |
| `questions` | id, passage_id, number, stem, options_json, question_source_type, version_group | 题目可保留多个文字版本 |
| `answer_keys` | id, question_id, correct_option(nullable), evidence, source_asset_id, verified_status | 答案来源和审核 |
| `practice_sessions` | id, paper_id, mode, started_at, finished_at, source_question_version | 一次独立训练 |
| `responses` | id, session_id, question_id, selected, is_guess, is_correct(nullable), submitted_at | 答题和结果 |
| `error_reasons` | id, response_id, reason_code, note, evidence_segment_id | 题目可多选错因 |
| `vocab_entries` | id, normalized_text, display_text, category, meaning, status, notes | 个人表达主条目 |
| `annotations` | id, entry_id, passage_id, revision_id, from_offset, to_offset, quote, prefix, suffix, context, status | 每处实际高亮 occurrence |
| `dictations` | id, session_id, passage_id, audio_segment_id, user_text, reference_snapshot, created_at | 听写版本 |
| `listening_flags` | id, session_id, passage_id, segment_id, issue_type, note | 听觉理解障碍记录 |
| `review_queue` | id, target_kind, target_id, due_date, status, completed_at | 有明确依据的复习队列 |
| `app_settings` | key, value_json | UI / 播放速度等设置 |

**关键约束**：音频时间单位统一 `ms`；前端 UI 显示 `mm:ss`；音频区间采用 `[start, end)`；文本位置偏移以同一规范化字符串/修订版为准；主词条与每次 occurrence 分离；删除原文件须显示引用影响并二次确认；备份需包含所有表与 assets 目录。

**搜索**：SQLite FTS5 索引 passages 文本与 vocab_entries.display_text / meaning；主数据库仍负责关系和过滤，不用 FTS 取代完整数据。

## 6. API 合同（建议 FastAPI，统一 `/api/v1`）

- `POST /assets/import` 多文件、角色可选 → import_job_ids；大文件上传显示进度。
- `GET /imports/{id}` → pending/processing/review_needed/success/failed + 错误细节；`POST /imports/{id}/confirm`。
- `GET/POST/PATCH /papers` 和 `GET /papers/{id}/outline` → 分类树和关联资产。
- `POST /papers/{id}/assets/link` → 绑定原件；`POST /passages/{id}/revisions` → 原文修订。
- `GET/POST/PATCH /audio-segments` → 音频时间标记；`GET /assets/{id}/stream` → 本地可 seek 的音频流，支持 Range。
- `GET/POST /questions` 与 `GET/POST/PATCH /answer-keys` → 题目与答案版本；`POST /sessions` `POST /sessions/{id}/responses` `POST /sessions/{id}/finish`。
- `POST /responses/{id}/reasons`、`POST /listening-flags`、`POST /dictations` → 诊断与听写。
- `GET/POST/PATCH/DELETE /annotations` → 原文标注与编辑。
- `GET/POST/PATCH /vocab`、`GET /vocab/{id}/occurrences`、`POST /exports/vocab` → 词库与导出。
- `POST /backups`、`POST /backups/restore`、`GET /health` → 备份/恢复/健康检查。

具体接口可按最小可用闭环依次实现。所有写操作必须返回真实 ID 和可再次 GET 的状态。不得用仅前端 mock 状态假冒后端已保存。

## 7. 推荐技术栈与运行方式

- 前端：Vue 3 + TypeScript + Vite；状态管理 Pinia；Vue Router；桌面优先 CSS Grid/Flex；可采用一套成熟组件基础（如 Naive UI / shadcn-vue），但需要统一样式。
- 后端：Python 3.11+ / FastAPI / SQLModel 或 SQLAlchemy；SQLite + migration (Alembic)。
- PDF：PyMuPDF 提取，PDF.js 用于原件查看；OCR 可用 Tesseract/PaddleOCR，初版以可离线部署、英文准确率和 Windows 安装可靠性为先。
- Word/TXT：python-docx 或 Mammoth；TXT 多编码处理；禁止不可信富文本原样插入 HTML。
- 音频：浏览器原生 HTMLMediaElement 为播放基准，wavesurfer.js 可做波形及 Region A/B 选区；20–30 分钟大型音频需要预生成 waveform peaks 或降级为时间轴，避免一次解码耗尽内存。
- 导出：Python CSV、openpyxl（XLSX 阶段）、JSON ZIP 完整备份。
- 部署：Windows 用户双击 `start.bat` 启动后端并打开系统默认浏览器到 `http://127.0.0.1:8000`；离线运行。生产打包不要依赖用户已安装 Node；如不打包，明确提供依赖安装脚本与日志。
- 数据目录建议：`D:\CET4-Studio\data\`，允许在设置中修改。数据库、原件、音频、导出、备份按子目录组织。
- 安全：本地仅 bind `127.0.0.1`，防路径穿越、限制文件类型与大小、验证 MIME、对 OCR 与 DOCX 的 HTML 结果消毒，不执行用户上传的脚本；备份恢复使用相对路径且验证 hash；所有网络增强功能默认关闭。

技术说明与参考（官方）：
- PDF.js https://mozilla.github.io/pdf.js/getting_started/
- PyMuPDF 文本提取 https://pymupdf.readthedocs.io/en/latest/recipes-text.html
- FastAPI 文件上传 https://fastapi.tiangolo.com/tutorial/request-files/
- wavesurfer.js https://wavesurfer.xyz/docs/
- SQLite FTS5 https://www.sqlite.org/fts5.html

## 8. 迭代任务（必须按任务+验收推进，不采用泛泛阶段口号）

### T0 工程骨架和 UI 框架
交付：可本地启动、路由、共享导航、暗/亮不必双模式但视觉一致、设置页、SQLite migration、真实数据读写、演示数据与真实资料明确隔离。
验收：双击运行可打开站点；关闭后重启没有丢任何真实数据；导航各页正常；没有假数据伪装真实学习记录。

### T1 混合资料导入 + 分类（P0）
交付：PDF 文字、DOCX、TXT、图片 OCR、MP3 导入，原件保存、预览与校对，年/月/卷/篇结构，关联音频。
验收：用一个文字 PDF、一个扫描图片、一个 DOCX、一个 TXT、一个 20min+ MP3 逐一导入，均能在页面找到；对于 OCR 错误可以编辑且原件仍可查看；相同 SHA256 文件提示重复。

### T2 听力播放器 + 手工分篇时间区间（P0）
交付：真实 MP3 播放、进度/跳转/倍速、A-B 循环、手工保存八个篇章时间区间、隐藏原文、句子/区间定位。
验收：导入 24min 音频不崩溃；选 News 1 直接进入对应区间；用户选定 20–40 秒区间重复播放不少于 5 轮，A/B 边界误差在一般桌面音频播放允许范围内（目标 ≤ 300ms，浏览器/编码差异需注明）；刷新后区间仍在。

### T3 鼠标标注 + 表达库（P0）
交付：任意词组选择、分类标色、重叠标注、注释、跨文章去重、来源跳转。
验收：同一原文 `to the point where` 与内部 `point` 可以共存并独立编辑；刷新不丢失；同一短语在三篇添加只出现一个词库主条目和三个出处。

### T4 真题做题 + 错因诊断（P0）
交付：A-D 答题、题号、录音/PDF 问句版本、答案来源、提交、猜测标记、错因多选、错题到音频跳转、不同会话成绩隔离。
验收：在无稿模式答完至少一篇录音、提交后查看成绩和错误原因；PDF 与录音问句冲突时分别显示，无法确认的答案不判为正确。

### T5 精听学习闭环（P0）
交付：隐藏/显示全文、听写与对比、句子定位、自评、无稿复听、薄弱点队列。
验收：一条“首听错题→标记词没听出→循环听20秒→选短语加标→复听→保留结果”链路能真实走通；任务结束后重开仍保留全过程。

### T6 导出 + 备份 + 质量验收（P0）
交付：CSV/TXT/JSON备份、筛选、导出预览、可恢复 ZIP、一键启动和 README、至少基础自动化测试。
验收：选仅听力+不会短语，导出与数据库统计一致；删掉本地工作副本后从备份在新目录恢复成功；测试并记录失败边界。

### T7 后续增强（P1，不抢占 P0）
XLSX/Anki 格式、可编辑快捷键、句级自动对齐建议、自动字典释义（可离线）、智能词汇复习、移动端适配、原文与音频来源冲突报告；**不得把这些功能作为跳过 P0 闭环的借口**。

### 每项任务的交付格式
DSH 每次必须报告：
1) 实际修改了哪些文件、实现了哪些可操作功能；
2) 怎么启动、测试输入是什么；
3) 测试命令与真实结果、关键 UI 截图（特别是听力工作台）；
4) 哪些验收通过/未通过、已知缺陷；
5) 下一个任务的准确范围，未完成项明确标记，不用“基本完成”等模糊话术。

## 9. 必须执行的端到端验收脚本

### CASE 01 原件和题目来源核对
导入同一套的 PDF、听力原文照片、MP3，编辑 2 道“录音题干与 PDF 文字不同”的示例。验收：能并存、明确来源、切换训练版；从音频关联的录音题干练习，不能自动使用 PDF 错误改写。

### CASE 02 音频定位、A/B 循环
导入整套超 20 分钟 MP3 → 手工绑定 News 1 的范围 → 选出 00:20–00:40 的任意 20 秒片段 → 0.75 倍速循环播放 → 暂停、继续、切回 1x → 刷新后查看保存的篇章时间段。

### CASE 03 首听 → 错因 → 精听 → 回测
新建单篇 session，隐藏字幕答两题 → 提交 → 对错误题标记“熟词没听出来” → 跳到答案对应音频 → 看原文将一个短语加入词库 → 隐藏原文重听 → 标记自己是否能说清内容 → 下次继续可以查看这次历史。

### CASE 04 跨文标注与去重
一段中标注 `point`（单词）和 `to the point where`（短语），再在其他两篇标注该短语 → 两个不同类型高亮均存在 → 词库短语仅 1 个主条目、3 处引用 → 进入每处定位正确。

### CASE 05 词库筛选导出
标注 10 条（含3条重复、含听力/阅读、掌握/不会混合） → 仅选择“听力·不会·短语”导出 CSV → 打开 Excel 检查中文编码、列结构、出处；统计条目与查询结果一致。

### CASE 06 断电/恢复模拟
进行导入、标注、改时间区间和答题后正常关闭后台 → 重启网站 → 全部数据可读取 → 创建 ZIP 备份 → 空白目录恢复 → 关键数据一致、原文件可打开。

### CASE 07 导入失败与文本修订
导入损坏文件或无法解码音频 → 页面提示明确错误且未写坏数据库；对已有原文做插入/删除后，旧标注能够可靠重定位或清晰标记“需人工修复”，绝不能悄悄标到错误文字上。

## 10. DSH 开发优先级与研发约束（开工指令）

1. **第一优先**：建立可运行骨架、完成混合材料导入，尽快打通整套音频中单篇播放与 A-B 循环；这是用户听力薄弱的直接需求。
2. **第二优先**：鼠标标注 + 生词库 + 可追溯出处；注释输入要少点操作。
3. **第三优先**：考试答题、错因诊断、听写/无稿回测、导出/备份。
4. UI 风格与上面规范一致，每个任务带至少一张真实截图；允许先完成手工时间关联，再加智能自动对齐。
5. 不要要求用户提前对所有材料逐字校对才能开始练习；解析不足可局部标记并继续其它材料。
6. 对所有“成功/完成”必须有数据验证，不用硬编码已完成百分比、虚假假成绩、示例列表冒充真实文件。
7. 在项目根目录维护 `README.md`、`docs/IMPLEMENTATION_STATUS.md`、`docs/ACCEPTANCE.md`、`docs/KNOWN_ISSUES.md`；每完成任务更新状态与可复现的命令。
8. UI 原型 HTML 若单独交付，只作为设计参考，不等同完成生产系统。需在 Vue 前端实现真实逻辑。

**最终验收一句话**：用户能够将自己的四级真题 PDF、听力原文、整套 MP3 导入本地系统，先隐藏原文做题，再针对薄弱 20 秒片段慢速循环、看原文标出不懂的单词或短语、复听检查理解，并将标注连同原文与出处导出；关闭重开完全保留数据。
